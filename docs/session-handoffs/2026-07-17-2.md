## Details (for the next Claude)
### What was done — 1 commit, pushed to `main` + deploying
`55ed417` **perf: cache public pages via cookieless service-client reads** — 9 files under `src/app/(public)/` + `docs/decisions.md`.

The core problem (from last session's handoff): every public page called `await createClient()`, which reads cookies via `next/headers` → forces dynamic render → `export const revalidate` was a no-op and Supabase was hit live every visit. The fix: read with the cookieless `createServiceClient()` (from `src/lib/supabase/server.ts`) so pages can cache. **But that client bypasses RLS**, so each query had to gain an explicit filter reproducing its table's RLS SELECT policy, verified per-page:
- `artists` → `.eq("status","active")` (RLS `status = 'active'`) — already present.
- `releases` / `videos` → no filter (RLS `USING (true)` — all rows public) — service client returns identical rows.
- `events` (flames-lounge) → `.eq("is_public", true)` (RLS `is_public = true`) — already present.
- `news_posts` → **the one real gotcha.** RLS is `is_published AND published_at <= now`. The old page filter used `.eq("is_published",true).or(published_at.is.null, published_at.lte.now)` — the `.or` is *looser* than RLS (it includes null-dated posts that RLS hides). Under the RLS-bypassing service client that `.or` would have started showing posts the live site currently hides. Replaced everywhere with `.eq("is_published",true).lte("published_at", now)` to mirror RLS exactly. Also: `/news/[slug]` `generateMetadata` had **no** publish filter at all (relied purely on RLS) → added the full clause so unpublished post metadata can't leak.

Per-file:
- `page.tsx` (home) — service client; news query tightened; `export const revalidate = 120`. → `○` static.
- `artists/page.tsx` — service client; `revalidate = 120`. → `○` static.
- `flames-lounge/page.tsx` — service client; `revalidate = 120`. → `○` static.
- `artists/[slug]/page.tsx` — both `createClient` calls → `createServiceClient` (getArtist keeps `status='active'`); `revalidate = 120`; added `generateStaticParams` (active artist slugs). → `●` prerendered.
- `releases/[slug]/page.tsx` — both calls → service client (releases/videos RLS true); `revalidate = 120`; `generateStaticParams` (all release slugs). → `●`.
- `news/[slug]/page.tsx` — service client; RLS-parity filter on all 4 reads (main + metadata + prev/next); `.single()`→`.maybeSingle()` to avoid noisy zero-row errors; `revalidate = 120`; `generateStaticParams` (published slugs). → `●`.
- `releases/page.tsx` — reads searchParams (dynamic). Wrapped the two searchParams-independent reads in module-scope `unstable_cache(..., ["public-releases-page"], { revalidate: 120 })`; filter/sort stay in JS. → `ƒ`.
- `videos/page.tsx` — same pattern (`getVideosData`, key `public-videos-page`): caches artists + all videos + public jobs; artist/kind filtering moved to JS. **Signed URLs minted per-request OUTSIDE the cache.** → `ƒ`.
- `news/page.tsx` — `getNewsPage(from, to)` in `unstable_cache` (key `public-news-list`), cached per page slice; RLS-parity filter. → `ƒ`.

**Signed-URL invariant:** generated-video/asset signed URLs have a 1h TTL and are always minted per-request (never inside `unstable_cache`), so a cached page can't serve an expired URL (120s revalidate ≪ 3600s TTL). This is why the videos/artist-detail pages keep a request-time `createServiceClient()` just for `createSignedUrls`.

### Gotchas & decisions this session
- **Service client bypasses RLS — every new public read MUST filter to public-only rows or it leaks.** This is now the load-bearing rule for public pages. Filters kept inline (not centralized in a `lib/public-data.ts`) so each page's reviewer sees them; considered and deliberately deferred a centralized module (revisit if filters get copy-pasted). See memory `public-pages-service-client-caching` and `docs/decisions.md`.
- **`news_posts` null-`published_at` behavior:** RLS hides null-dated published posts; the old `.or` filter would have shown them. The conversion deliberately preserves the *live site's current* behavior (hide them) by mirroring RLS with `.lte`, not the page's old apparent intent.
- **Why not tag-based invalidation:** user explicitly chose **time-based** (120s) to keep the change self-contained to the public pages and avoid touching every admin `actions.ts`. Content changes rarely; a ≤2-min delay is invisible. Tag-based is the documented upgrade path if instant updates are wanted.
- **searchParams forces dynamic regardless of cookies** — that's why `/releases` `/videos` `/news` can't be static even after removing cookie reads; their DB reads are cached via `unstable_cache` instead. `generateStaticParams` (not `revalidate` alone) is what turns the `[slug]` pages from `ƒ` into prerendered `●`.
