### Gotchas & decisions this session
- **RLS lockdown may bite future code:** any code that changes `profiles.role/is_bartender/artist_id` or `artists.status/slug` MUST use the service client (or run as admin) — a session/anon `.update()` now throws by design. Don't loosen the triggers; route through a service-role action. (memory: `rls-privileged-column-triggers`.)
- **Void design = the owner's call:** canceling a sale is an *un-sell* — restores stock AND logs to `pos_voids` (owner wanted cancellations visible in reporting, not silent). Optional reason, any staff can void (ledger provides accountability), prompt-Cancel keeps the item as a mis-tap guard.
- **`price_cents × qty` fix:** old `removeTabItem` under-subtracted the tab total for multi-qty lines — fixed alongside the stock work.
- **Public-page caching is blocked (deferred deliberately):** `await createClient()` reads cookies → dynamic render, so `revalidate` won't cache Supabase queries. Fixing needs cookieless reads + per-page public-only-filter security review. High value, not quick.
- **Profit-aggregation RPC deferred:** shipping unverified money-summing SQL to prod (no local DB to test) is the "never deploy unverified money math" risk. Indexes were the shipped mitigation; the all-time Sales query is still an unbounded JS aggregation.
