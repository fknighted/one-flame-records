### Gotchas & decisions this session
- **No local Docker → migrations went straight to PRODUCTION**, with explicit user authorization ("you run it, I verify"). **Order matters:** apply the migration *before* deploying code. Old code tolerates the new columns (additive), but new code that `select`s `cost_cents` would break tab creation if the column were absent. This session applied-then-pushed each time, so prod was always consistent.
- **`...0001` made a bad seed assumption** — it expected a single item literally named `'Rum'` to rename. Production actually had `'Rum Shot'`, `'J B Rum Shot'`, `'Rum - Half Flask'` (two brands + a half flask). Caught by the verification script (a check failed), fixed in `...0002`. **Lesson: query the live menu before writing seed UPDATEs.**
- **`bottle_yield` is an editable default, not fixed** — owner said rum comes in 750ml *and* 1L bottles (≈16 vs ≈22 × 1.5oz shots), so units-per-bottle is entered/overridable at add-time; the column just prefills it.
- **Whole-bottle model = shared pool** (owner's explicit choice over separate stock): a bottle SKU has `bottle_parent_id` → its shot SKU; selling one calls `decrement_pos_item_stock_by(parent, parent.bottle_yield)`; enabled only while `parent.stock > bottle_yield` (so the last bottle is never sold whole). Cost snapshot for a bottle = `parent.cost_cents × bottle_yield`. Bottle SKUs are hidden from inventory *add* lists (you restock the shots) and show "pooled / from shots" in the admin manage table.
- **Profit basis = cost locked at sale** (owner's choice): `pos_tab_items.cost_cents` snapshots the item cost at sale time, so editing a cost later never rewrites past profit. `cost_cents` on `pos_items` holds the *latest* purchase cost (last-cost, not weighted average).
- **Sections are display-only** (`menu_section`): they regroup the inventory pages and cluster the POS tabs, but the POS `category` (drink/beverage/food/snack/game_time) used by the order screen tabs and sales report is unchanged. Fever + Rum Cream classified as **Rums** per owner.
- **Open Tabs = `status in ('open','away')`** — `away` = "customer left, tab locked unpaid, collect later" (pre-existing status). Both are outstanding money.
- **`.playwright-mcp/`** is an untracked artifact in the working dir — deliberately not committed; harmless.
- Pre-existing quirk left untouched: `incrementTabItem` bumps a line's quantity without re-decrementing stock. Profit is unaffected (uses `quantity × cost_cents`).
