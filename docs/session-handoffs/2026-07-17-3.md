### Gotchas & decisions this session
- **You CAN verify money SQL against prod without admin creds.** The service-role key is in `.env.local` (`SUPABASE_SERVICE_ROLE_KEY` + `NEXT_PUBLIC_SUPABASE_URL`). This session's `scratchpad/verify-bar-sales.mjs` used it to fetch raw rows (paginated past the 1000-row cap) + reduce in JS, and diffed that against the RPC output — exact match across all periods. This is the go-to for the `price_jmd` money change. To load `@supabase/supabase-js` from an ESM script outside the project dir, use `createRequire("<project>/package.json")` — a bare import won't resolve from the scratchpad.
- **Deploy ordering for RPC work is load-bearing:** push the migration to prod *first* (`npx supabase db push --linked`), *then* commit + push the calling code. Otherwise the deployed page calls a function that doesn't exist. Both this session's migrations went first. The migration is additive/safe (nothing calls the RPC until the page deploys), so pushing it early — even before final verification — is fine and reversible (`CREATE OR REPLACE` to fix).
- **Postgres EXECUTE grants:** `CREATE FUNCTION` grants EXECUTE to `PUBLIC`, and `anon`/`authenticated` inherit through PUBLIC — revoking those roles individually is a no-op. Must `REVOKE … FROM PUBLIC` then `GRANT … TO service_role`. Both migrations do this.
- **Cent sums must be bigint.** All-time bar revenue (~$112k JMD already = 11.2M cents) will pass int4's ~2.1B-cent (~$214k) ceiling; `admin_*_counts` use int (row counts are safe), but `bar_sales_*` cast money sums to bigint.
- **Bar COGS is $0 in prod right now** — `pos_items.cost_cents` isn't entered, so profit == revenue everywhere. That's the known data-entry gap, *not* a bug; the verification confirmed revenue/per-category revenue (non-zero) match, and the cost SQL is structurally identical to the validated revenue SQL.
- **Whole-dollar rounding is per-figure**, so a displayed profit can differ from displayed-revenue − displayed-cost by $1. Acceptable for a whole-dollar currency; noted in `decisions.md`.
- No local Docker → Supabase types can't be regenerated; new RPC signatures are **hand-added** to `src/types/supabase.ts`. `Args: never` for no-arg RPCs.
